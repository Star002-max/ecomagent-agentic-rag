# 数据字典与指标口径

所有价格与收入使用人民币元。金额从整数分计算后写入CSV；百分比以小数存储，例如0.06表示6%。CSV本身没有类型约束，因此验证脚本会重新检查数值、日期、主键和引用。

## 数据字典

| 文件 | 粒度与字段 | 说明 |
|---|---|---|
| products.csv | 每个SKU一行；sku、product_name、category、price、rating、review_count | sku唯一；price为整个180天不变的单价；rating是本数据集中全部评价均值，保留4位小数；review_count为明细条数 |
| sales.csv | 每个SKU每天一行；date、sku、orders、units、revenue、sessions、conversion_rate | date与sku组成唯一键；orders为订单数，units为件数，一个订单可以包含两件商品 |
| inventory.csv | 每个SKU每天一行；date、sku、inventory | inventory是当天销售完成后的期末库存，不能跨天相加当作当前库存 |
| reviews.csv | 每条评价一行；date、sku、rating、review_text | 每个SKU每天模拟两条评价；同一日期和SKU允许多行，甚至相同评分和文本；没有客户或订单归因 |

日期为无时区业务日期，采用ISO格式YYYY-MM-DD。products中的评分及评价数是数据截止日快照，不是某一历史日的已知值。后续历史区间分析必须筛选reviews明细，避免使用未来评价。

## 销售与转化

- 当日收入 `revenue = units × price`。本阶段不模拟折扣、税费、退款或运费。
- 单日转化率 `conversion_rate = orders / sessions`，不是 `units / sessions`。
- 周期转化率 `sum(orders) / sum(sessions)`。不能使用每日转化率的简单平均。
- 转化率CSV字段保留10位小数；汇总时使用原始订单和访问数重新计算，不能累计舍入后的每日比率。
- 周期订单、件数、收入、访问量可相加。不要把销售额称为销量：本项目销量特指units，销售额特指revenue。
- 环比变化率 `(本期 - 上期) / 上期`。比较期为0时返回未定义，不输出0%或无穷大。
- 转化率百分点变化 `(本期转化率 - 上期转化率) × 100`；它与相对变化率是不同指标。

例如两天分别有1单/10次访问和9单/900次访问，总转化率为10/910≈1.0989%，不能算成(10%+1%)/2=5.5%。

转化率从6%降至3.6%：相对下降40%，下降2.4个百分点。测试中专门设置访问量差异很大的例子，以捕捉错误的简单平均。

默认模拟集每天访问量为正；校验辅助函数仍区分零访问量、零转化和空区间：有访问但零订单是0%转化；零访问的转化率未定义；空区间表示没有数据，各项指标为None。相关函数仅用于Phase 1验证，不是提前实现的查询服务。

## 库存

- 当前库存取数据截止日记录，而不是库存之和或平均值。
- 近期日均销量 `最近30天总units / 30`。必须先验证30天完整，不能把缺失日期视为零销售。
- 估算可售天数 `当前库存 / 近期日均销量`；若日均销量为0，应标记无法据此估算。
- SKU003验收要求可售天数小于3天，其余商品大于7天。这是模拟场景的验证阈值，不是适用于所有商家的经营标准。
- 可售天数只用于简单演示，未考虑需求预测、在途补货、交货周期或促销。
- 库存期末值满足 `今日库存 = 昨日库存 + 今日补货 - 今日units`。验证器检查推算补货量非负；SKU003从第二天起推算补货量必须为0。首日开盘库存由生成规则定义，CSV未单列。

## 评价

近期均分对所选日期的每条评价求平均，评价数使用明细条数。跨天且每天评价数量不同时，不能直接平均每日均分。本模拟集恰好每天两条，不代表实际业务恒定如此。

SKU005评分下降与转化下降同时发生，是人工设置的关联现象，不能由此证明评分下降导致转化下降。评价文本也是模拟文本，不含真实个人信息。

## 比较窗口

分析基准日固定为数据的end_date。最近30天为 `[end_date-29天, end_date]`，之前30天为 `[end_date-59天, end_date-30天]`，均包含起止日。最近30天不等于自然月；本阶段不实现自然月查询服务。

数据设计和清单属于开发验证资料，不应在后续阶段放入RAG知识库，避免Agent直接读取预设答案。
